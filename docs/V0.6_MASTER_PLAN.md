# DocuForge v0.6 Master Plan

## Purpose

DocuForge v0.6 transforms the current documentary CLI pipeline into a modular AI Content Factory.

The main goals are:

- Interchangeable providers
- Multiple content templates
- Local-first media and voice support
- Compatibility with the existing Supertonic workflow
- Pexels image and video integration
- Local TTS and cloned voice integration
- Easier extension through registries and plugins
- No mandatory dependence on paid APIs

---

The following features already work and must not be broken:

- Typer CLI

# Non-Negotiable Requirements

## Existing Supertonic System

The existing Supertonic installation must not be modified or broken.

DocuForge will integrate with Supertonic through an adapter layer.

Never:

- Delete Supertonic files
- Replace its environment
- Change its existing dependencies
- Modify its production directories without explicit approval
- Install DocuForge packages into the Supertonic environment

DocuForge must remain isolated in its own virtual environment.

---

## Local-First Philosophy

DocuForge must support local and free tools as first-class providers.

Required local integrations:

- Pexels images
- Pexels videos
- Local TTS
- Locally hosted cloned voice
- Supertonic renderer
- FFmpeg
- Local media library

Paid APIs must remain optional.

# Sprint 1 — Provider Registry

## Goal

Create a shared registry for all provider categories.

Provider categories:

- Text
- Image
- Video
- Voice
- Render
- Storage
- Upload

## Planned Structure

```text
app/providers/
├── __init__.py
├── base.py
├── registry.py
├── defaults.py
├── text/
│   ├── deepseek.py
│   ├── openai.py
│   ├── gemini.py
│   └── local.py
├── image/
│   ├── pexels.py
│   ├── local_library.py
│   └── flux.py
├── video/
│   ├── pexels.py
│   ├── local_library.py
│   └── kling.py
├── voice/
│   ├── local_tts.py
│   ├── cloned_voice.py
│   └── elevenlabs.py
└── render/
    ├── supertonic.py
    └── ffmpeg.py
```

## Provider Interface Examples

```python
text_provider.generate(prompt)

image_provider.search(query)

video_provider.search(query)

voice_provider.synthesize(text, output_path)

render_provider.render(project_dir)
```

## Acceptance Criteria

- Providers are resolved by key
- Provider-specific logic is not hardcoded inside agents
- DeepSeek continues working
- Existing CLI commands remain functional
- `.env` selects default providers
- Unknown providers fail with clear errors
- Unit tests cover registration and provider lookup

# Sprint 2 — Template Engine

## Goal

Support different content types using the same engine.

Initial templates:

- documentary
- news
- shorts
- finance
- technology
- educational

## Example Commands

```bash
docuforge build --template documentary "Kara Delikler"

docuforge build --template news "Tesla yeni model tanıttı"

docuforge build --template shorts "Dünya 5 saniye dursa ne olur?"
```

## Template Responsibilities

Each template may define:

- Prompt directory
- Pipeline stages
- Default duration
- Aspect ratio
- Language
- Media strategy
- Voice strategy
- Render strategy

## Planned Structure

```text
templates/
├── documentary/
│   ├── template.json
│   └── prompts/
├── news/
│   ├── template.json
│   └── prompts/
├── shorts/
│   ├── template.json
│   └── prompts/
└── finance/
    ├── template.json
    └── prompts/
```

## Backward Compatibility

This command must continue working:

```bash
docuforge build "Kara Delikler"
```

It must behave as:

```bash
docuforge build --template documentary "Kara Delikler"
```

## Acceptance Criteria

- Documentary remains the default template
- Each template selects its own prompt set
- Templates may define different pipeline stages
- Invalid templates produce clear errors
- Build and resume support templates
- Project metadata stores selected template

# Sprint 3 — Pexels Media Adapter

## Goal

Connect storyboard scenes to Pexels image and video search.

## Required Capabilities

- Search Pexels images
- Search Pexels videos
- Download selected media
- Save attribution metadata
- Store results per scene
- Prevent duplicate media where possible
- Support retries and rate limits

## Media Fallback Order

Default:

```text
Pexels Video
→ Pexels Image
→ Local Media Library
→ AI Image Provider
```

Config example:

```env
MEDIA_FALLBACK_ORDER=pexels_video,pexels_image,local_library,ai_image
```

## Output Structure

```text
projects/<project>/
└── media/
    ├── scene_001/
    ├── scene_002/
    └── manifest.json
```

## Acceptance Criteria

- Every scene receives a media result or explicit failure state
- Pexels API key is read from `.env`
- Media is cached
- Download errors do not corrupt pipeline state
- Attribution is preserved
- Existing image and video prompt files remain available

Required providers:

- Local TTS

## Output

```text
projects/<project>/

    ├── scene_002.wav

```

## Acceptance Criteria

- Local TTS works without paid APIs
- Cloned voice is selectable
- Existing model files are not copied into Git
- Voice output is normalized
- Failures are recorded in pipeline state
- Provider switching requires no code changes

# Sprint 5 — Supertonic Adapter

## Goal

Connect DocuForge outputs to the existing Supertonic video workflow.

## Integration Strategy

Use an adapter instead of modifying Supertonic internals.

DocuForge prepares:

- Project metadata
- Scene order
- Media files
- Narration audio
- Captions
- Timing information
- Render manifest

Supertonic consumes the prepared package.

## Planned Output

```text
projects/<project>/
└── render/
    ├── manifest.json
    ├── timeline.json
    └── assets/
```

## Acceptance Criteria

- Supertonic installation remains untouched
- Adapter path is configurable
- Dry-run mode exists
- Render manifest can be inspected before execution
- Existing Supertonic commands remain usable
- Adapter failure does not delete project assets

# Git Workflow

For major work:

```text
main
└── feature/provider-registry
└── feature/template-engine
└── feature/pexels-adapter
└── feature/supertonic-adapter
```

Rules:

- Never commit `.env`
- Never commit API keys
- Never commit cloned voice model files
- Never commit downloaded media
- Never commit generated projects
- Prefer small, reversible commits
- Test before merge
